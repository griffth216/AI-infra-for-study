GEMM（General Matrix Multiply，通用矩阵乘法）是线性代数中的一个基本操作
对于矩阵A和B，标准形式位C=mAB+nC（A：M * K B：K * N， C：M * N，mn为标量）
$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

**$Q$ (Query, 查询)**、**$K$ (Key, 键)**、**$V$ (Value, 值)** 都是高维矩阵

假设我们有一个输入序列
![](https://picx.zhimg.com/v2-4b95cc1195f24ed86c97c467a2fdce4d_1440w.jpg)
每个x_i就是一个 token （词元 / 标记，最小的处理单元）的 embedding（嵌入 / 向量，高维的浮点数数组（向量）），比如一个词、一个字、或者一个图像 patch。 如果我们直接用这些x_i之间做点积，它确实能反映出两个 token 的相关性（越大越相关），但存在两个致命问题：

1. **每个 token 的表示是静态的：输入 embedding 没有区分谁在关注别人还是被别人关注。**
2. **无法表达不同的关注模式：所有 token 的关系都被一个固定空间描述，模型无法灵活学习不同角度的相似性。**

于是就引出了 Q、K、V 的设计。
## **二、Q、K、V 的线性变换在干什么？**

### **1.投影到不同子空间**
输入的特征维度是 d_model，每个 token 的 embedding 包含**所有语义信息**。
直接用原始 embedding 做 Q/K/V，相当于在同一个空间计算相似度，模型**无法学习不同语义关系的权重**。
我们把输入 ( X ) 分别线性变换成三种表示：
![](https://pic1.zhimg.com/v2-89a62a6610c7e3bf47ea015d89d4d50e_1440w.jpg)
- **Query（查询）：表示我想关注什么信息**
- **Key（键）：表示我是什么样的信息**
- **Value（值）：表示我携带的信息内容**
![[Pasted image 20260602104037.png]]
这三个矩阵其实是从同一个输入 (X) 投影出来的三种**视角**。 这一步的作用，就是**让模型在不同子空间中理解 token 之间的关系**。
### **2.支持多头注意力

多头注意力机制：
人类语言是极其复杂的，一个词在句子中往往同时承担着多种不同的逻辑关系。
假设我们有一句话：**“小明昨天吃了一个非常甜的红苹果”**。
当我们以“苹果”作为查询中心（$Q$）去观察其他词时：
- **动作关系：**“苹果”需要强烈关注“吃了”（动宾关系）。
- **属性修饰：**“苹果”需要强烈关注“甜的”**和**“红”（形容词修饰）。
- **数量关系：**“苹果”需要关注“一个”。
如果只有一个注意力机制（单头），模型就必须在一个权重分配表中去平衡所有这些信息。它可能会把 33% 的注意力给“吃了”，33% 给“红”，33% 给“一个”。结果是每种信息都学得不深，变成了“一锅乱炖”，甚至丢失关键细节。
多头注意力（Multi-Head Attention）的思路是：既然一双眼睛看不过来，那我就给模型装上 $h$ 双眼睛（通常是 8 个、12 个或 96 个“头”）。
如果只有一个注意力机制（单头），模型就必须在一个权重分配表中去平衡所有这些信息。它可能会把 33% 的注意力给“吃了”，33% 给“红”，33% 给“一个”。结果是每种信息都学得不深，变成了“一锅乱炖”，甚至丢失关键细节。

多头注意力其实是**把这个基础公式并行执行了多次，然后做了一个“拼接”操作**。
$$\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \text{head}_2, \dots, \text{head}_h)W^O$$
$$\text{head}_i = \text{Attention}(Q W_i^Q, K W_i^K, V W_i^V) = \text{softmax}\left(\frac{(Q W_i^Q)(K W_i^K)^T}{\sqrt{d_k}}\right)(V W_i^V)$$

##### 第一步：分发任务，降维投影
在单头注意力中，我们只有一组投影矩阵。而在多头注意力中，假设我们要分出 $h$ 个头，模型就会学习 $h$ 组**完全独立的**权重矩阵（$W_i^Q, W_i^K, W_i^V$）。

原始的高维词 Embedding（比如 512 维）会被这 $h$ 组不同的权重矩阵，分别“投影”到 $h$ 个**不同的低维子空间**中。比如分 8 个头，每个头处理的维度就是 $512 \div 8 = 64$ 维。

##### 第二步：并行计算（各自运行你的公式）

现在，每个“头”都拿到了属于自己的、只有 64 维的 $Q_i, K_i, V_i$。它们**独立且并行**地执行你之前提到的缩放点积注意力公式。
在 GPU 内部，这 8 个头的矩阵乘法不是排队做的，而是高度并行同时计算的。它们各自生成了一份 64 维的特征向量，代表该头提取到的专属信息（比如语法头提取到了“被吃”，属性头提取到了“红色”）。

#### 第三步：拼接与融合（Concat & Linear）

现在，8 个头都算出了自己的结果（8 个 64 维的短向量）。
模型将这 8 个短向量**首尾相连（Concatenate）**，重新拼成一个完整的 512 维长向量。

为了让这 8 种不同的信息能够真正融合在一起，最后还会乘以一个全局的输出权重矩阵 $W^O$。这个 $W^O$ 的作用就像是智囊团的主席，负责把 8 个专家的独立报告进行总结提炼，输出最终的决策结果。
你可能会想：搞那么多头，计算量不是翻了倍吗？
这就是 Transformer 设计的精妙之处。因为每个头在第一步时，把维度切分变小了（从 512 变成了 64）。**8 个 64 维的小矩阵乘法的计算量，其实和 1 个 512 维的大矩阵乘法几乎是一模一样的！**
也就是说，多头注意力在**不增加整体计算复杂度**的前提下，让模型拥有了从多个不同维度理解语言的能力。



### **3.增加可学习参数**
每个线性变换 W_Q, W_K, W_V都是 **可训练权重**，模型可以自动学习如何对不同 token 的embedding 做不同的查询、匹配和加权。这使得 self-attention 不只是一个固定的相似度计算，而是一个 **可调节、可优化的语义匹配函数**。

> [!NOTE] self-attention
> **它发生在同一个句子内部。** 句子自己看着自己，句子里的每一个词，都在和其他所有的词进行信息交互。

### **4.便于下游操作**

QK^T 计算的是注意力权重，如果不做线性变换，模型只能依赖原始 embedding 的内积，这种相似度空间不一定适合 softmax 加权。
线性变换可以把 embedding 投影到更适合做**注意力匹配**的空间，提高学习能力。


## **三、Q 与 K 的点积**
拿到 Q 和 K 后，self-attention 计算的是每个 Query 与所有 Key 的相似度：
![[Pasted image 20260602115929.png|407]]
这里的点积代表**匹配程度**，即：
- Q_i 表示第 i 个 token 想关注的信息；
- K_j 表示第 j 个 token 所包含的信息；
- 它们的点积越大，说明第 i 个 token 越应该关注第 j 个 token。
从计算上看，点积是将所有的对齐分量相乘并累加；从几何上看，当向量指向相似方向时，点积为正，如果向量垂直，点积为0，当向量方向相反时则为负数。

这样，我们就得到了一个注意力分数矩阵，表示每个 token 对其他 token 的**注意力权重**。

## **四、为什么要用 Softmax？**

### 1. **把“相似度”变成“权重分布”**

点积结果可以是任意实数，而 Softmax 会把它们压缩到 ( [0, 1] ) 区间，并且所有权重之和为 1。 这让注意力分数能被解释为概率分布，即模型在关注谁、关注多少。
### 2. **放大强关注、削弱弱关注**
Softmax 有指数特性，会让大的分数更大、小的分数更小，从而突出主导注意力。 这在语义建模中非常关键——模型不会平均地看所有 token，而是能**聚焦重点**。
### 3. **梯度稳定性**
如果直接用点积做加权，分数可能过大或过小，导致梯度不稳定。 Softmax 保证了数值范围可控，梯度传播更平滑。

## 五、$\times V$ 的本质：一场精准的“加权求和”（Weighted Sum）

经过 Softmax 后，我们手里有一组加起来等于 1（即 100%）的权重分数。

**$\times V$ 的操作，其实就是拿着这组百分比，去把对应的 $V$ 向量按比例混合起来。**

假设我们现在正在计算“苹果”这个词的最终输出，Softmax 给出的权重表是这样的：

- 给“甜”分配了 **20%** 的注意力。
- 给“苹果”自己分配了 **10%** 的注意力。

## 为什么说“上下文向量”是 NLP 领域的终极圣杯？
在 Transformer（自注意力机制）诞生之前，AI 界使用的是**静态词向量**（比如 Word2Vec）。那时候，词典里的每一个词都有一个固定的高维坐标。
- 无论你输入的是“我吃了一个**苹果**”，还是“**苹果**公司发布了新手机”。
    
- 在以前的 AI 眼里，这两个“苹果”的底层数字向量是**完全一模一样**的。
    
- 这就像一个死板的字典，只管字面意思，不管语境。

**上下文向量（结果向量）**，彻底打破了这个僵局！经过 Attention 机制的洗礼：
- “我吃了一个**苹果**”里的“苹果”向量，吸收了“吃”的属性，它的坐标在空间中向着“水果、食物”的区域**发生了移动**。
    
- “**苹果**公司发布了新手机”里的“苹果”向量，吸收了“公司、手机”的属性，它的坐标向着“科技、企业”的区域**发生了移动**。
    

这就是大模型“智能”的源泉——**它输出的不再是一个死板的词，而是一个“活生生的、随着语境千变万化的概念”。**
算出了这个包含丰富上下文的动态向量后，它要交接给谁？

在一个完整的大语言模型（比如 GPT-4 或 Gemini）中，这只是一层（Layer）的工作：

1. 这个融合了当前语境的向量，会被送入一个叫作 **前馈神经网络（FFN, Feed-Forward Network）** 的地方，进行一次深度的非线性思考和特征提取。
    
2. 然后，它会作为全新的输入（取代最初始的词向量），**进入下一层的自注意力机制**！
    
3. 这种“看上下文 $\rightarrow$ 融合 $\rightarrow$ 再看更广的上下文 $\rightarrow$ 再融合”的过程，在大模型内部会重复几十次甚至上百次（比如 96 层）。
    

经过几十层的叠加和提炼，最初那个简单的词元，最终变成了一个包含着语法、逻辑、甚至人类常识的极其复杂的**高维思维结晶**。模型正是拿着这个最终的结晶，去预测下一个词该说什么。
